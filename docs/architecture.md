# Portfolio implementation

## Page structure

The implementation uses six independent pages: Home, About, Skills, Work, Expertise, and Connect. Each has a physical HTML entry and its own title, description, canonical URL, and pre-rendered content. Browser navigation loads documents normally; no React Router, history interception, or SPA fallback is used.

This updates the initial review's single-page recommendation to follow the owner's request for a structured, multi-page implementation.

## Rendering

1. `vite.config.ts` registers all HTML entry points.
2. Its `portfolio-static-pages` plugin reads each entry's `data-page` and renders `App` with React's `renderToString`.
3. `App` composes the appropriate page inside `SiteLayout`.
4. Metadata, structured data, and populated markup are injected into each HTML document.
5. Vite bundles CSS and JavaScript and emits a sitemap.
6. `main.tsx` loads the relevant page module and hydrates the existing markup.

The shared layout contains navigation, footer, and progressive entrance effects. The server and browser receive the same normalized base path to keep hydration and URLs consistent. Production and production preview default to `/whoIam/`; development defaults to `/`.

Page-specific modules are split into separate chunks. Home and Skills share Motion for the badge, process sequence, and skill filtering. Most other effects use CSS and IntersectionObserver. All content is visible in generated HTML; entrance effects are applied only after hydration to elements below the fold. Reduced-motion preferences disable those effects.

## Home process sequence

`src/components/Process.tsx` owns the four-step journey; content remains in `src/data/portfolio.ts`, and its layout is isolated in `src/styles/process.css`. The desktop introduction stays in view beside alternating, pinned cards. A dashed curved connector fills with scroll progress. Each card smoothly gains color, settles, and returns to its neutral state as it passes through the viewport. Scrolling upward reverses the same sequence.

Motion tracks stationary rows rather than transformed cards and smooths the progress with springs. Text switches between black and white according to the panel's calculated luminance, preserving contrast during intermediate color states. On phones, cards stack beside a narrow curved rail. Reduced-motion visitors receive still, neutral cards; all four steps are readable before hydration and without JavaScript.

## Content ownership

The Skills page owns an independent HTML entry, metadata, hydration module, and gallery. `src/data/skills.ts` defines 131 tools/practices in eight groups and their search aliases; `src/components/SkillLogo.tsx` handles local technology marks and graceful symbol fallbacks. `src/styles/skills.css` owns the constellation, gallery, sticky filter controls, and responsive layouts. Local SVGs and provenance live in `public/skills/`, generated by `scripts/generate-skill-logos.mjs` from pinned development dependencies. The first gallery render is populated HTML. Filtering uses Motion layout transitions and live result announcements; no proficiency scores are inferred from the resume.

`src/data/portfolio.ts` owns profile facts, projects, expertise, process, dated career roles, recognition, and industry domains. `src/data/pages.ts` owns page metadata. `src/data/media.ts` controls optional media.

The supplied eight-page resume remains unchanged in `public/resume/`. Resume details replace the previous 18+ years summary with 19+ years, add exact career dates and both degrees, and refine project contributions. Existing recognition/community information remains. Customer names are omitted from website project descriptions.

The site's contact options use the supplied professional email and existing LinkedIn/GitHub profiles. The copy control reports actual clipboard success or failure. There is no simulated contact form or message-delivery claim.

## Optional portrait and video

The supplied JK portrait is configured as a transparent WebP shared by Home and About. It fits fully in the ID card above decorative orbit lines, with a small JK corner mark; loading failures restore the large monogram. The original photograph remains unchanged. See `portrait-edit.md` for the built-in imagegen prompt and encoding details. A configured video enables the hero reel control, which supports play/pause and reports failed playback. Video does not autoplay.

Portrait asset paths and presence on both generated pages are covered by the integration checks. Transparency was verified after WebP encoding, and both ID-card layouts were inspected in the browser. Video playback remains to be checked when a video is supplied.

## Styling

CSS is separated by responsibility: design tokens, base rules, layout, shared components, page composition, and responsive overrides. Tailwind's Vite integration is available for utilities alongside the custom design system.

The default palette uses near-black, warm vermilion, and cream. Cream large text against the accent has a calculated contrast of approximately 3.17:1. Body text uses darker ink on accent/light sections and a high-contrast muted tone on dark panels.

- Every generated local link, asset path, and fragment checked against `dist/` at the GitHub Pages subpath.
- Resume signature and unchanged copied bytes verified.
- Seven detailed projects and six sitemap entries verified.
- Live production preview inspected on desktop and phone.
- All pages checked for horizontal overflow at 320, 390, 768, and 1440 CSS pixels; none detected.
- Normal page navigation, project deep links, the ten-role career disclosure, copy-email success, and mobile menu Escape/focus restoration checked in the browser.
- No warning/error console logs were observed during page navigation.
- Skills navigation, eight category controls, combined search/filter behavior, MCP/RAG aliases, clearing search, empty results, reset, direct reload, and mobile menu Escape/focus restoration checked in the browser. Its layout was checked at 320, 390, 768, and 1440 CSS pixels with no horizontal overflow; loaded logos showed no failures.

These are targeted checks, not a formal accessibility certification. Email links hand off to the visitor's mail application; no email was sent during validation. Home's introduction reel was checked for muted first-visit autoplay, manual-only return visits, Play/Stop reset, completion reset, and sound toggling. See `intro-video.md` for its processing and playback behavior.

## Deployment

GitHub Actions validates `main` pull requests and uploads the built static artifact. A separate deployment job runs only for pushes/manual runs. Repository Pages settings must use GitHub Actions. No deployment was performed during this implementation.
